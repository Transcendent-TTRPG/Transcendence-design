# Questions

Each file in this tree should define one balance or behavior question.

Questions should name:

- the scenario
- the actors
- the policies
- the metric set
- the comparison being made

## Minimum rule for Techniques

Every Technique that aims to close as validated should normally have at least
one saved question about its current `Rhythm` / `Attrition`.

That minimum question should usually compare the Technique against one of:

- a base action baseline
- a sibling Technique in the same origin
- the next lighter or next heavier step in the same ladder
- a nearby alternative that trades damage for control, geometry, or persistence

## Derived question families

When a Technique leans on a clear secondary surface, it should usually also
define a derived question for that surface.

Typical examples:

- `ailments`
  - persistence
  - cleanup / recovery burden
  - later activation pressure
- `concealment`
  - gain rate
  - detection rate
  - crossing or reposition success
- `procedural states`
  - persistence
  - cleanup path
  - effective burden frequency
- `reactions`
  - trigger frequency
  - opportunity rate
  - cost efficiency
- `positioning` or `geometry`
  - meter/angle swing
  - line recovery
  - path denial
- `breaking`, `zones`, or `parts`
  - disable rate
  - tactical consequence
  - swinginess
- `kits`, `residues`, or consumable setup`
  - whether access friction or cleanup already constrains value enough

## Practical intent

Without a saved question, a Technique may be:

- authored
- published
- and even `runtime_supported`

but it is still not strongly validated for balance.
